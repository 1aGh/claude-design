title: Next.js recipe

---

Assumed: existing Next.js 15+ app, pnpm or npm, Tailwind, App Router.

## 1. Install the marketplace + CLI

In Claude Code:

```text
/plugin marketplace add 1aGh/md-claude
/plugin install flow@md-claude
/plugin install design@md-claude     # optional, only if you want canvas-first design
```

Then in your terminal:

```bash
npm i -g @1agh/md-claude              # or pnpm add -g
```

## 2. Scaffold the `.ai/` workspace

```bash
mdcc init --name my-app
```

Open Claude Code in the repo root and run:

```text
/flow:init
```

The onboard command auto-detects your stack and writes `.ai/workflows.config.json`. For a Next.js + Tailwind + Vitest app you'll typically end up with:

```json
{
  "name": "my-app",
  "language": "en",
  "theme": "dark",
  "platforms": ["web-desktop", "web-mobile"],
  "stack": {
    "language": "typescript",
    "framework": "next.js",
    "packageManager": "pnpm",
    "monorepo": false,
    "ci": "github-actions",
    "tests": "vitest",
    "css": "tailwind",
    "router": "next-app"
  },
  "conventions": {
    "branchingModel": "github-flow",
    "commits": "conventional"
  },
  "responsive": {
    "approach": "mobile-first",
    "densityMap": {
      "web-desktop": "command-center",
      "web-mobile": "palm-friendly"
    }
  }
}
```

## 3. (Optional) Set up the design plugin

Create a `.design/` directory at the repo root:

```bash
mkdir -p .design/system .design/ui
```

Drop your design tokens (CSS variables, JSON, whatever) into `.design/system/`. Boot the dev server:

```bash
mdcc design serve --port 4399
```

Open `http://localhost:4399`. New canvases are scaffolded via `/design:new` inside Claude Code:

```text
/design:new HomeHero "marketing hero with feature carousel"
```

## 4. Try the loop

```text
/flow:setup-prd          # one-time: draft the PRD
/flow:plan "<feature>"   # per-feature: draft a phase plan
/flow:execute            # implement it
/flow:done               # validate → commit → PR → archive
```

## Gotchas

- **App Router only.** The plugin's defaults assume `next-app` router. If you're on Pages Router, set `stack.router: "next-pages"` and accept that the design-system-guard's a11y checks for `<Link>` semantics will lean toward App Router idioms.
- **Tailwind v4.** Works fine. The design plugin's CSS-token system is framework-agnostic — Tailwind tokens live in `tailwind.config.ts`, design tokens in `.design/system/`. Keep them in sync via a DDR if you decide to dedupe.
- **Vercel deploy.** `/flow:release` walks the `releaseGuide` runbook, not a Vercel-specific flow. If your release process is just "push to main → Vercel deploys", your runbook can be a single H2 saying so.
