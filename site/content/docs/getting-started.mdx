Three commands and you're in. (Maybe four. Depends on your shell.) Five steps below, four of them optional. `npm install` and a handful of slash commands. No accounts, no API keys, no telemetry.

## 1. Install the marketplace

Inside Claude Code:

```text
/plugin marketplace add 1aGh/maude
/plugin install design@maude
/plugin install flow@maude
```

Install one or both, they're independent. `/plugin marketplace update maude` pulls future releases.

## 2. Install the CLI (optional, recommended)

```bash
npm i -g @1agh/maude
# or skip the global install:
npx @1agh/maude --help
```

This gives you `maude`. The binary that scaffolds the `.ai/` workspace and boots the design dev server. See [CLI](/docs/cli) for the full surface.

## 3. Scaffold a project

```bash
maude init --name my-app
```

Copies the `.ai/` skeleton from the flow plugin into your repo:

```
.ai/
├── workflows.config.json   # the only file you usually edit
├── decisions/              # DDRs (Design Decision Records)
├── plans/                  # phase plans + archive
├── state/                  # STATE.md, HANDOFF.md
├── docs/                   # PRD, codebase map
├── retros/                 # post-feature retros
└── scenarios/              # cross-platform UI scenarios
```

For richer setup (stack auto-detect, branching model, changelog provider), run `/flow:init` inside Claude Code instead. It calls `maude init` first, then asks the right questions.

For `CLAUDE.md`, use Claude Code's built-in `/init`. Don't write it by hand.

## 4. Run a slash command

Three good first commands:

| Command | What it does |
| ------- | ------------ |
| `/flow:status` | Tells you where you are. Safe to run anywhere. |
| `/flow:plan "<feature>"` | Drafts a phase plan grounded in your PRD + design system. |
| `/design:new <Name> "<brief>"` | Scaffolds a new design canvas under `.design/<name>/` and iterates on it. |

After the plan lands, `/flow:execute .ai/plans/<plan>.md` walks the implementation. `/flow:done` validates, commits, opens a PR, and archives the plan.

## 5. Boot the design dev server (optional)

If you've installed the `design` plugin and you have a `.design/` directory:

```bash
maude design serve --port 4399
# → http://localhost:4399
```

The server injects an inspector overlay into every HTML canvas. **Cmd+Click any element** to scope `/design:edit "<feedback>"` to that selection.
