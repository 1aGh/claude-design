# `@md-claude/site` — Documentation site

Public documentation for the `mdcc` CLI and the `flow` + `design` plugins. Built with [Fumadocs](https://fumadocs.dev) + Next.js 16 (App Router) + Tailwind v4 + Orama (client-side search).

## Run locally

From the **repo root** (pnpm workspace):

```bash
pnpm install                          # install root + site deps in one pass
pnpm --filter @md-claude/site dev     # → http://localhost:3000
# shortcut:
pnpm dev:site
```

The site is not part of the published npm package — it deploys separately (Vercel, see Phase 2 Task 6).

## Layout

```
site/
├── app/                          # Next.js App Router
│   ├── (home)/                   # marketing / landing
│   ├── docs/[[...slug]]/         # docs pages
│   ├── api/search/route.ts       # Orama search endpoint
│   ├── llms.txt/                 # llms.txt route handler
│   ├── llms.mdx/docs/[[...slug]] # raw MDX for LLM consumption
│   └── og/docs/[...slug]/        # OG image generation
├── content/docs/                 # the actual MDX pages
├── lib/
│   ├── shared.ts                 # appName, route constants, gitConfig
│   ├── source.ts                 # Fumadocs `loader()` wiring
│   └── layout.shared.tsx         # shared nav/footer
├── components/mdx.tsx            # MDX component overrides
├── source.config.ts              # Fumadocs MDX config + Zod schemas
└── next.config.mjs               # `withMDX()` wrap
```

## Authoring

- Add or edit MDX under `content/docs/`.
- Frontmatter: `title`, `description` required. Optional `full: true` for full-width pages.
- Folder + `meta.json` controls sidebar order — see [Fumadocs Source API](https://fumadocs.dev/docs/headless/source-api).
- Re-run `pnpm --filter @md-claude/site dev` (or just let Next.js hot-reload).

## Search

Client-side via Orama. New MDX files are picked up on next build — no manual indexing.

## Deploy

Target: **Vercel** (project [`md-claude`](https://vercel.com/iagh/md-claude) in team `iagh`). Custom domain: `md-claude.iagh.cz`. See [DDR-005](../.ai/decisions/DDR-005-docs-site-stack-and-hosting.md) for the why.

Vercel's **native GitHub integration** handles deploys — push to `main` ships production; PRs get automatic preview URLs (commented on the PR). No GitHub Actions workflow needed.

### Project settings on Vercel

| Setting | Value |
| ------- | ----- |
| Root Directory | `site` |
| Framework | Next.js (auto-detected) |
| Build Command | `next build` |
| Install Command | autodetected (pnpm) |
| Production Branch | `main` |
| Custom Domain | `md-claude.iagh.cz` (auto-managed — `iagh.cz` uses Vercel nameservers) |
| Env (production) | `NEXT_PUBLIC_SITE_URL=https://md-claude.iagh.cz` |

### Auto-generated reference content

`content/docs/reference/` is generated by `pnpm gen:reference` (= `node scripts/build-{command,schema}-reference.mjs`). It's **committed** to the repo because Vercel uploads only `site/` — the build cannot reach `../../plugins/` siblings.

Workflow: after editing `plugins/{flow,design}/commands/*.md` or `plugins/flow/.claude-plugin/config.schema.json`, run `pnpm --filter @md-claude/site gen:reference` and commit the diff. The `prebuild` script also runs the generators, but gracefully no-ops when source dirs aren't present (e.g. during the Vercel build).

### Manual deploy from a clone

```bash
cd site
npx -y vercel@latest deploy --prod --yes      # production
npx -y vercel@latest deploy                    # preview
```

The CLI uses your personal Vercel auth (`vercel login` once). For maintainer-only manual operations.
