# Tauri v2 desktop shell — command + permission gotchas

- **`permissions/autogenerated/*.toml` are COMMITTED SOURCE, not build output.** For a brand-new `#[tauri::command]`, `cargo check`'s `build.rs` validation step runs *before* the proc-macro side-effect that would generate the matching permission file — so a first-time addition fails with `Permission allow-<cmd> not found` even though the command is correctly written and registered. Hand-author `permissions/autogenerated/<command_name>.toml` once, mirroring an existing sibling file's exact shape (e.g. `take_pending_deep_link.toml`), then add `"allow-<command-name>"` to `capabilities/default.json`.
- **A custom command's bare function name must not collide with a registered plugin's own internal command name** (e.g. `tauri-plugin-notification` already has its own internal `notify` command). Tauri's ACL codegen silently fails to generate a permission for the app-level command in that case — `cargo check` reports "Permission not found" listing every *other* valid permission, with no hint that the cause is a name collision. Pick a distinct name (e.g. `send_notification`, not `notify`) for any command wrapping a plugin that might expose a similarly-named command of its own.
