# Feature — Draw animation: keyframe IR (authoring) + Lottie-from-code (web+mobile delivery)

> Decision: [DDR-094](../decisions/DDR-094-draw-animation-keyframe-ir-native-authoring-lottie-export.md).
> Skill spec: [`notes/design-to-lottie-skill-spec.md`](notes/design-to-lottie-skill-spec.md).
> Grounded in the studyfi-v3 mascot session (StudyFi DDR-011 + its execution report +
> system review), a 2026-06-05 deep-research pass on SMIL→Lottie, and a **working POC**
> (same day). Extends the static draw engine (DDR-070) + composition layer (DDR-074).

## TL;DR (the outcome)

- **Authoring stays native in maude.** A general **keyframe IR** (timeline of property
  tracks on any node) is the cross-platform animation source; maude is its editor
  (`/design:draw` + motion utils). It extends the DDR-067 single-source invariant from
  static geometry to time.
- **Production delivery = Lottie emitted from code**, via **`/design:to-lottie`**
  (alias `/design:to-rn`). ONE `.lottie` renders 1:1 on **web** (`lottie-web`/
  `dotlottie-react`) **and mobile** (`lottie-react-native`) — 1:1 by construction
  (same renderer family), performant (native Lottie runtime). This is **validated** by
  a full POC.
- **Native rn-svg/Reanimated renderer is a FALLBACK** for light/occasional animation.
  A POC port proved fidelity is possible but hit real walls for rich animation
  (`feTurbulence` has no native impl; continuous `d`-morph froze the app; two
  hand-matched impls drift). See Findings.
- **Workflow:** iterate native in maude → at productionizing (e.g. in `/flow:execute`)
  call `/design:to-lottie` → one Lottie for web + mobile.

## Background — the studyfi-v3 pain

The draw engine (DDR-070) + critics (DDR-074) are **100% static**: no animation
primitive, `draw-proof` renders only still artboards, the rubric never mentions motion.
So an "animated mascot" brief produced a still frame, and animation fell to ad-hoc
hand-authored CSS/SMIL in `/design:edit`. The studyfi-v3 fire mascot session showed the
cost: ~3 rounds on a dead mechanism (CSS `d:path()` doesn't animate live; a freeze-frame
falsely "confirmed" it), mechanism thrash, the final morph variants generated by a
**Python perturbation outside the engine** (bypassing "draw as code"), and re-discovered
gotchas (CSS `transform` overrides `transform=`; SMIL ignores the CSS RM catch-all).

Two questions followed: (1) how should the draw layer support animation natively, given
the user requirement *"animate sequences of anything, scalable"*; (2) once polished in
maude, how does it ship to the StudyFi RN app (where SMIL doesn't survive `react-native-svg`)?

## Findings (deep research + two POCs, 2026-06-05)

**Deep research (6 angles, 23 sources, 25 claims verified):** there is **no production
SMIL→Lottie converter** (lottie-web #62, 8 years), and **After Effects rejects animated
SVG**. So the only reliable bridge is to **emit from the keyframe data**, not convert
rendered SVG. Lottie maps cleanly: vertices → `ty:sh` bezier `ks`; `keySplines` → `i/o`
handles 1:1; `linearGradient` → `gf`. Lottie has no reduced-motion in the format (host-
gated) and bakes color (runtime override).

**Native rn-svg/Reanimated POC** — full fire-mascot port (`Mascot.tsx`). Fidelity is
achievable (morph via worklet vertex-lerp, masks, gradients, blink, tremble), BUT three
real limits surfaced:
1. **`feTurbulence`/`feDisplacementMap` have NO native impl** in react-native-svg 15.x
   (JS-only stubs; no iOS `.mm` / Android `.java`) → procedural texture can't render
   natively; must be pre-baked.
2. **Continuous multi-layer `d`-morph froze the whole app** — rn-svg re-parses a Path's
   `d` on every change and re-renders the whole `<Svg>` on any child update; with SVG
   `<Filter>`s in the tree it ran an offscreen pass per frame. Even isolated, it sits at
   rn-svg's perf ceiling.
3. **Two hand-matched implementations drift** — the port kept missing nuances (pre-jump
   tremble, mouth grit→yell) because it chased the web by eye. "Guaranteed 1:1" is
   impossible by construction when web and native are separate renderers.

**Lottie-from-code POC** — a python-lottie generator (`_to-lottie.py`) emits ONE
`.lottie` from the same flame keyframe data + the `_layout.css` `.mascot--fire`
choreography, **self-verified by rendering frames through the real lottie-web runtime**
(`agent-browser` screenshots of an HTML embedding `lottie.min.js`; cairo can't render
masks). Result: morph + fire-shoot envelope (overshoot easing), masked Minion eyes +
blink, mouth grit→yell, aura flash, tremble — all from code, identical web↔mobile,
performant. **This is the validated primary path.**

## Decision

**Lottie emitted from code is the primary production delivery for rich/continuous
animation, web AND mobile (one artifact, both platforms). Native rn-svg/Reanimated is
the fallback for light animation. Authoring stays native in maude; the keyframe IR is
the source that feeds a `toLottie()` serializer (primary) and native serializers
(fallback).** Full rationale in DDR-094.

## Conversion rules — CSS/SMIL → Lottie (the load-bearing findings)

What `/design:to-lottie` MUST encode (each found the hard way in the POC):

1. **Per-segment easing from the real CSS tokens.** `cubic-bezier(x1,y1,x2,y2)` → apply
   the same `Bezier((x1,y1),(x2,y2))` to **every** keyframe (each kf gets `o=(x1,y1)` +
   `i=(x2,y2)` → every segment exact). **Preserve overshoot (`y>1`)** — `--ease-out
   (0.34,1.42,…)` is the "snap"; a generic smooth easing kills it. Each animation uses
   its OWN token (body/lids/mouth/aura = ease-in-out; fire-shoot = ease-out; morph = keySplines).
2. **Port EVERY animated property** — enumerate from the CSS (the POC first dropped the mouth).
3. **Arc commands (`A`) → parse with python-lottie (`parse_svg_file`)**, never hand-approximate.
4. **Lottie `layers[0]` = top** (and within a layer, first shape = top): build back→front,
   then **reverse** the layer list (parenting resolves by `ind`, so reversing is safe).
5. **Masks** (eye/mouth clipping) render on lottie-web/RN but NOT in cairo → **self-verify
   through headless lottie-web**, not cairo.
6. **Incommensurate sub-loops** (flame flicker vs master) → bake the flicker across the
   comp duration; **hide the loop seam in an invisible phase** (here: the extinguish).
7. **Coordinate offset + baked static transforms** — shift the viewBox origin into the
   comp; bake static `translate/scale` into vertices; only ANIMATED transforms become
   keyframes (jump on a parent null; flame envelope as a layer scale about the base).
8. **Gradient opacity stops** appended after color stops in the flat array (`count` =
   color-stop count) — for soft glows + tip fades.

## P0 — the animation IR + native authoring serializers + live verify

The foundation; unchanged by the delivery flip — the IR feeds `toLottie()` (primary) and
the web/native serializers.

### P0.1 — Animation IR module (`draw/animate.ts`)
- React-free root (DDR-067). `Keyframe = { t, value, ease?: cubicBezierHandles }`;
  `Track` = keyframes on one property (`d` shape morph **vertex-array valued**,
  `transform`, `opacity`, gradient stops); `Timeline = { dur, begin?, repeat?, tracks,
  stagger? }`. **Stagger + sequence composition** for choreography ("animate sequences of
  anything"). Unit tests: compose, stagger, easing round-trip.

### P0.2 — `morphVariants()` producer (vertex-array, deterministic)
- `morphVariants(basePath, { n, jitter, seed })` → a `d`-track of **vertex arrays** with
  an identical command template / fixed vertex count (the cross-renderer interpolability
  constraint). Replaces the ad-hoc Python perturbation. Pure; unit-tested for invariance.

### P0.3 — Web authoring serializers: IR → SMIL + IR → motion/JSX
- `serialize` extends so one node-tree-plus-`Timeline` emits SMIL for the `.svg` form and
  `motion`/WAAPI for the JSX form. RM gate for both; position-vs-animation split. Test:
  SVG↔JSX parity for an animated mark (DDR-067 invariant, time-generalized). (For maude
  preview/authoring; production delivery is Lottie.)

### P0.4 — `_draw-motion-rules.md` (motion companion to the rubric)
- Mechanism ladder (envelope → CSS transform; shape morph → motion/SMIL, never CSS `d:`);
  the gotchas; the live-verify rule; the RM-gate pattern. Read by `draw-agent` + critic.

### P0.5 — Live-motion proof gate (`draw-proof --motion`)
- Sample an animated property over real wall-clock time (`getBBox()` t0 vs t1); assert it
  changes. Freeze-frame pass + over-time fail ⇒ HARD fail. Reuses screenshot machinery.

### P0.6 — Wire `draw-agent` + critic motion branch
- Motion brief → read `_draw-motion-rules.md`, plan the timeline, generate via IR
  producers, run `--motion` proof. Verdict gains a `motion` block.

## P1 — Production delivery (web + mobile) + external-asset path

### P1.1 — `/design:to-lottie` skill (PRIMARY — VALIDATED by POC)
- Emit ONE `.lottie` **from code** (IR / disciplined SMIL+CSS) → 1:1 on web
  (`lottie-web`/`dotlottie-react`) AND mobile (`lottie-react-native`).
- Built via python-lottie; **self-verified through headless lottie-web**. Algorithm +
  the 8 conversion rules + the self-verify recipe: [`notes/design-to-lottie-skill-spec.md`](notes/design-to-lottie-skill-spec.md).
- Reachable via `maude design to-lottie` (DDR-062); ships the generator + verify harness.
- Productionizing handoff (e.g. inside `/flow:execute`). Output: one Lottie + web/RN usage snippets.
- A future TS `toLottie()` engine serializer (from the IR directly) supersedes the
  python-lottie generator once P0's IR lands; the generator is the proven reference until then.

### P1.1b — `/design:to-rn` native renderer (FALLBACK — light animation only)
- `react-native-svg` + Reanimated component from the IR (reference: `Mascot.tsx`):
  worklet vertex-lerp morph, gradients (colors as props → theme-aware),
  `useReducedMotion()`, View-transform body motion. **Light/occasional animation only** —
  continuous rich morph hit rn-svg's perf ceiling and `feTurbulence` has no native impl.

### P1.2 — Reference-adapt sub-mode + license-at-fetch HARD gate
- Sanctioned "look like THIS external asset" branch: fetch the license **first**, surface
  options, record provenance, then adapt. Default stays engine-first. (Fixes studyfi-v3 D5.)

## Risks

- **Engine surface** (IR + serializers + producer + proof + the Lottie emitter). Land
  P0.1–P0.2 behind tests first; keep producers pure.
- **Lottie fidelity drift** if the conversion rules aren't followed — encode all 8 in the
  skill + the self-verify-through-lottie-web gate (catches it).
- **Lottie theming/RM costs** — colors baked (runtime override), RM host-gated. Acceptable
  for delivery; documented.
- **Two web mechanisms (SMIL + motion) for authoring** — collapse to one later if redundant.

## Out of scope

- Physics/particle simulation, video, full app-level motion choreography (stays
  `/design:edit` + flow `motion-rules`).
- Lottie/Rive as an **authoring** format (rejected — DDR-094). After Effects (rejects animated SVG).
- A converter of *rendered* SVG/SMIL (none reliable exists; emit from code instead).

## Verification

- **P0:** unit tests (IR compose/stagger, vertex invariance, SVG↔JSX parity); a `--motion`
  proof flagging a dead `d:path()`.
- **P1.1:** `/design:to-lottie` on a disciplined mark emits a Lottie that, rendered through
  headless lottie-web, matches the web reference arc; the same file plays in
  `lottie-react-native`. (POC done — see below.)
- **P1.1b:** the fallback renderer animates a light mark smoothly on device.
- **P1.2:** a reference-adapt run surfaces a license before integrating.
