# SYNC DECISION CORPUS — DISTILLED (source: 26 DDRs + feature-sync-file-plane plan + ground-truth doc, all read in full)

Legend: **IMMUTABLE** = standing invariant, redesign must satisfy it; **REVISITABLE** = a scope-cut or shape choice the redesign may change (constraints inside it noted); **SUPERSEDED** = already replaced, cite only for history.

## 1. PER-DDR DIGEST

**DDR-110 — Three-lane collaboration model (2026-06-16).** Split "what syncs how" into: Lane 1 distribution = git only (no hub materialization of canvases you didn't pull), Lane 2 live overlay = Yjs (edits/annotations/comments persist; presence ephemeral), Lane 3 TSX code body = soft artboard lock, never CRDT text-merge and never a merge UI. Why: a debate proposed ripping out Yjs "to save git history" — factually wrong (disk is a git-owned projection of the Y.Doc, DDR-064/051), and UX research showed hard sync gates and edit-save-push-only both fail (Abstract's tombstone). Also fixed vocabulary (Save version/Publish/Get latest; `merge`,`push`,`branch` banned in UI) and repo+branch as the IA primitive. **Status: MIXED.** IMMUTABLE: keep Yjs live overlay (never delete it on the false premise), prevent-don't-merge for TSX, no hard sync gate, the vocabulary contract. REVISITABLE (de facto already revised): Lane-1 "git-only distribution, no hub-propagation of create/delete" — the cloud arc has since shipped tombstones, asset lanes, and the file plane, all of which materialize files without git pull. The redesign should explicitly re-state what Lane 1 means for linked/cloud projects instead of pretending DDR-110's version still holds.

**DDR-064 — One shared Y.Doc per canvas (2026-05-29).** Two Y.Docs per canvas (collab room + hub provider) reconciled through disk was the textbook side-channel anti-pattern; a live race (stale in-memory doc re-persisting over a hub-pushed change) proved Phase 9.1 could narrow but never close it. Decision: one doc, both providers + disk binding attached; disk becomes a loop-free debounced projection; file edits ingest as diffs tagged `FILE_IMPORT`; origin sentinels; migrate-seed picks ONE authoritative source (the applyUpdate-duplication trap). Shipped behind `MAUDE_SHARED_DOC`, default OFF out of caution not a known bug. **IMMUTABLE (principle): never two replicas reconciled by copying whole values through a side channel.** The desktop still running the flag-OFF two-doc agent path is the *unfinished cutover*, not a counter-decision — the redesign may (should) finish it, never reverse it.

**DDR-052 — Hocuspocus over PartyKit (2026-05-27).** Self-hostability was the hard constraint ("deploy a hub feels like Tailscale"); PartyKit's production target is Cloudflare Workers only, defeating the no-lock-in thesis. Hocuspocus: native multi-document routing, persistence as extension, onAuthenticate hooks, plain-VPS, MIT, redis scale path. **REVISITABLE only on its own named triggers** (TipTap paywalls it, or a DO-native rewrite post-GA per DDR-193's fallback list) — nothing in the sync redesign requires re-litigating the transport; treat as settled.

**DDR-213 — Cell pairs with itself, loopback shared doc (2026-08-06).** The cell held two disjoint Y.Doc worlds (hub documents ← desktop; studio-child rooms ← browsers) joined only one-way via disk; two people on one project never met. Fix: the studio child runs a HocuspocusProvider to its OWN cell hub over loopback with `MAUDE_SHARED_DOC=1`, preserving DDR-209's fears as literal machine-checked conditions: (1) loopback-only hub URL, (2) autocommit never constructed (`MAUDE_SYNC_NO_AUTOCOMMIT=1` — hub's `afterStoreDocument` stays the only committer), (3) shared-doc must be on. Credential = boot-minted scope-`*` store token, never `HUB_SECRET`; config supplies only `workspaceId`, never a URL. Closed the entire DDR-064 pre-cutover checklist (slug collisions exclude BOTH files; pinned-room cap 500; comments hub→disk capped). Named residual: wildcard non-expiring pairing token (same shape as the pre-existing `HUB_SECRET`, documents-only). Also discovered the **container watcher gap** (recursive fs.watch misses atomic tmp+rename) and closed it for projection writes only, via self-announced `fs:any` (path-keyed coalescing). **Conditions IMMUTABLE; shape REVISITABLE via the sanctioned C1 follow-up** (re-home browser collab directly onto the hub Hocuspocus — one doc, no loopback hop, no minted token, fixes attribution) — DDR-213 explicitly calls C2 the reversible pilot that *earns* C1.

**DDR-209 — One studio, three shells (2026-08-03).** Deleted the 469-line studio reimplementation in the hub; the real `apps/studio` runs inside the cell behind an authenticating proxy. Containment vocabulary *reclassified, not loosened*: the invariant's real test is **EVALUATION on vendor compute, never serving bytes** (the cell builds, the browser evaluates); `/_canvas-shell` + `/_canvas-runtime` moved to a `SANDBOXED_ROUTE_PREFIXES` list valid only while the out-of-process empty-env import-allowlisted build is boot-asserted; +7 secret-bearing surfaces joined the forbidden list. One engine one host (sandbox moved INTO the studio's workspace path). "No route served by two implementations." Role per-request from the proxy; studio's read-only gate defaults closed in cloud builds. **IMMUTABLE** (both the evaluation-test wording and the no-second-implementation rule — the B3 lesson).

**DDR-193 — Tenant cells + containment invariant (2026-07-28).** Cloudflare end-to-end; one container per project (isolation you can point at — no `WHERE tenant_id` to get wrong); ephemeral disk ⇒ durability = R2 replication + rehydrate. **The one line: no tenant-authored TSX is ever evaluated by vendor-operated compute** — enforced by boot-assert + CI grep, not asserted; any future feature needing to break it has Direction B (structured non-executable unit) as a hard prerequisite. Lifecycle: export e-mail always fires before teardown; export always available. Operator trust: no standing access, break-glass is customer-visible, EU. **IMMUTABLE** (the invariant is explicitly "not renegotiable in a sprint").

**DDR-194 — Hub identity + durability (2026-07-28).** scrypt (not the token HMAC) for passwords with parameter refusal against memory-bomb rows; indistinguishable login failures in body AND timing; offboarding revokes exact-match owner + live sessions; XFF trusted only from configured proxy CIDRs, rightmost-untrusted-hop; persistent sliding-window rate limit; **the backup deliverable is the restore DRILL** (VACUUM INTO, manifest-written-last, CI-run, can fail); hand-rolled 4-verb SigV4 because the hub image is the DDR-054 "untrusted to peers" component and its dep surface must stay auditable. **IMMUTABLE** security posture (SigV4 revisitable only if multipart is ever needed — its own stated trigger).

**DDR-195 — Cell = same server minus routes; content-addressed assets; append-only autosave (2026-07-28).** A cell is the studio server with forbidden surfaces PRUNED, then `assertContainment` runs as a post-condition on the pruned table (prune-then-assert — the two can't disagree); withheld routes 404, never 403. **Content addressing IS the asset security model**: idempotent push, no invalidation, and verifiable pull — bytes must hash to their name or are refused (the hub may refuse to serve, it must never be able to substitute). **No presigned URLs in canvas content** (CSP `img-src 'self'` + a presigned URL is a bearer credential inside the least-trusted content); media rides the authenticated proxy (affordable only because R2 egress is $0 — provider choice is load-bearing). `assets/` prefix never GC'd (git history references it). Mirror failure never fails a local save. Cell commits append-only, author=human committer=bot, unknown = "Unknown editor" never the bot, quiescence batching, disk write FIRST, `pushMirror` refuses to resolve non-fast-forward (absence of a force flag is pinned by test). **IMMUTABLE** throughout.

**DDR-198 — Server-owned git history (2026-07-29).** The hub commits (headless agent on `afterStoreDocument`), using the **desktop's own `createAutoCommit` engine** — one commit engine, never two copies of the rules where "history is never rewritten" lives (Docker context widened to repo root to keep the single source). **Twins allowed only with a byte-equal drift test** against the real studio source (`meta-merge.mjs`, `workspace-files.mjs`). Working tree is the authority on paths (unknown slug lands flat, never in an invented directory). Shutdown is ours (`stopOnSignals: false` — the library's exit(0) ate the final flush of most sessions). §6 "assets swept from checkout, hub never an upload endpoint" — **that half is SUPERSEDED by DDR-217**; the rest **IMMUTABLE** (one-engine rule, twin-with-tripwire rule, "run the image, tests are the beginning of verification").

**DDR-199 — Cells on Cloudflare, four platform facts (2026-07-29).** Cell derives FROM the hub image (one dependency tree). Data plane is a SEPARATE Worker from the control plane (`wrangler deploy` deletes undeclared custom domains — it unrouted a live tenant mid-phase). Tenant hostnames are Worker custom domains (wildcard routes fail on TLS/pattern rules). `startOptions.envVars` REPLACES image ENV (list everything explicitly). A container rollout needs a deployed Worker version. Per-tenant secrets DERIVED via HMAC from a master that never enters a container. **A cell has no console** ⇒ `/health` reports boot facts (checkout present, seed, storage, canvas count) unauthenticated. Durability spike PASSED: checkout rides in the SAME backup generation as documents (mixed-generation restore = weeks of "app bug" corruption). **IMMUTABLE** (platform facts + derived secrets + self-describing health).

**DDR-102 — Cold-start divergence resolution (2026-06-11).** The founding data-loss incident (stale peer overwrote a day of work; 65/83 canvases never synced; boot printed "83/83 syncing" before any handshake). Decisions: per-machine **content-hash journal** (not timestamps) gates fast-forward — hub-wins overwrite allowed only when local hash == last-reconciled hash; **cold-start decision table is a pure module consumed by BOTH sync paths**; conflict = dual snapshot then newest-wins, **fail-closed** — if the loser's snapshot didn't land, the destructive overwrite is REFUSED and local seeds up; `syncMeta.bodyEditAt` stamped in the same transaction as every body apply; comments = id-union never a winner; one multiplexed WS per hub; valid/invalid rate buckets split; rejection reasons cross the wire verbatim; honest status after handshakes settle. **IMMUTABLE** (this + 223 is ground-truth invariant #1). The one revisitable part: the decision *table* is shared but the *apply code* exists twice — unify appliers, never weaken the table.

**DDR-076 — Empty hub doc never clobbers (2026-06-02).** A fresh hub truncated all 73 canvases of a real project to 0 bytes on first connect: the HTML branch treated `docHtml === ''` as authoritative while every sibling lane already guarded emptiness. Rule: **empty doc = "hub has no state yet", never an authoritative blank; seed local UP** (refuse-but-don't-seed was rejected — the hub would stay empty forever and the project never converges). **IMMUTABLE.**

**DDR-214 — One honest sync-status rule (2026-08-07).** "Syncing 75 canvases" then silence: monitor born `online`, first-match aggregate, counts only rose, status bar never read `docs`, `remoteGap` enumerated the files that had just arrived. Fix: **one pure presentation function read by every surface** (agreement structural, not remembered); monitor seeded `connecting`; disconnect demotes; `auth-rejected` sticky; `pulled` means what arrived. Adversarial amendment: **fail closed — `synced` must be a positive assertion, the pessimistic branch is the default**; **ordering is a security property — a refusal outranks unreachability outranks any count** (else a hostile hub silences documents by refusing then dropping the socket). Known unfixed: a hub that handshakes then silently stops ACKing still reads synced (needs an out-of-band liveness round trip). The rejected "Connect Run sheet" (persisted per-document ledger with confirmed round trip) has an explicit revisit trigger — **the ground truth's "doručenka" requirement IS that trigger firing**. Principle **IMMUTABLE**; the ledger alternative is now due.

**DDR-217 — Cloud asset transport: desktop pushes (2026-08-10 + addendum 08-11).** Doc lanes carry only text, so cloud rendered grey boxes. Options killed by facts: git-remote pull (seed strips credentials from origin; desktop and cell histories are deliberately separate), lazy fetch (cell can't reach a NAT'd desktop; bucket doesn't have the bytes either), binary-in-Yjs (memory amplification, immortal update history, no merge semantics for immutable blobs — **do not extend the CRDT lane vocabulary for files**). Chosen: `PUT /assets/<key>` on the existing authenticated route — bearer-gated, anchored-regex key shape, streaming temp+rename with per-file cap, workspace-gated; HEAD-before-PUT idempotent boot sweep. Addendum: there are **TWO asset classes** — content-addressed uploads (`assets/<sha8>`, bucket-served) and DS/brand assets (`system/<ds>/assets/…`, checkout-served, full-path referenced) — the first pass moved only class 1, so every DS logo stayed grey; added `PUT /_asset-file/<rel>` with the heavier gate set (some-segment-`assets`, **binary-extension allowlist as the load-bearing backstop against data→code writes**, realpath containment, write to the RESOLVED parent — the TOCTOU fix). **Lane structure REVISITABLE** (the redesign's "one transport" question targets exactly this); the caps/validation/idempotence/each-boundary-validates-its-own-input constraints are **IMMUTABLE**.

**DDR-222 — Resync is restart; sweep out-of-process (2026-08-12).** The full sweep segfaults Bun 1.3.3 when run beside the dev server (isolated: standalone 182/182, in-process 3× SIGSEGV + bus error), taking the whole editor with it. Resync = the existing `syncControl.restart()` (serialized, refuse-early 409), no new lifecycle. Sweep runs in a spawned child (same `resolveBunPath`/BUN_BE_BUN discipline as the canvas sandbox — DDR-177); a dead child is a *reported* failed sweep; **no in-process fallback** (it would reintroduce the crash exactly where staging broke). NDJSON progress; credential in a 0600 file never argv; cancel kills the child (idempotent uploads + temp-then-rename make it safe); 10 s cooldown because a restart re-authenticates every document (DDR-102 bucket math); both routes main-origin-only, both halves asserted. **REVISITABLE in shape** — if a redesign eliminates the mass walk+hash sweep, the child process can go — but the surviving fact is **IMMUTABLE: full-sweep-class work (mass hashing/walking) never runs in-process next to the editor** (DDR-225 qualifies the wall: a single fetch is fine).

**DDR-223 — Per-lane annotations stamp; emptiness never beats content (2026-08-14).** The annotations eraser: cold start resolved annotations by the BODY winner, and the 72-byte empty wrapper (`strokesToSvg([])`) is a non-empty string that defeats every `!== ''` guard — a stale hub wrapper erased newer strokes **in both architectures**, and with the strokes went the `assets/<sha8>` references asset-pull scans (hence "broken frame forever"). Decisions: `syncMeta.annotationsEditAt` stamped in the same transaction at every apply site (cold-start seeds stamp with FILE mtime so stale content can't claim freshness); `decideAnnotationsColdStart` as a pure table in both architectures; **unstamped emptiness never beats content** — semantic emptiness detection (`isEmptyAnnotationsSvg`), stamped-newer emptiness IS honored (a deliberate delete-all), live delete-all propagation untouched. Residual: constant-wrapper self-echo in UI state only. **IMMUTABLE**, and generalize it: *every* independently-editable synced lane needs its own edit stamp, and "empty" must be recognized semantically per format, never as string-emptiness.

**DDR-224 — Checkout serves first; every write door mirrors; arrival heals (2026-08-15).** Four stacked holes, one symptom: (1) `GET /assets/` was bucket-only — the cell served a file to browsers from its checkout while 404ing peers on the same file; (2) `PUT /_asset-file/` had no mirror hook — files lived checkout-only, one container teardown from gone (and one rollout DID lose them); (3) `sweepNew` failed structurally silently (failures in `result.failed`, nobody read it, function never rejects); (4) browsers never retry a failed image — bytes arrived, glyph stayed broken until manual reload. Decisions: checkout-first bucket-fallback serving ("the checkout is what this cell can serve; the bucket is the durable copy"); every checkout write door fires `onWritten → sweepNew`; mirror results loud + one 60 s retry; new HMR mode `asset` that re-points broken `<img>`/`<image>` (heal, not reload — a fresh link pulling hundreds of files must not be a reload storm). **IMMUTABLE direction** — the ground truth's "one store of serving truth" redesign question is the *completion* of this DDR (bucket demoted to pure write-behind durability, probe semantics simplified), not a revision of it.

**DDR-225 — Fast lanes beside the sweep (2026-08-16).** With correctness fixed, latency was the complaint: desktop→cloud minutes (debounce → spawn → full-walk), cloud→desktop 20 s poll. Added `pushOneAsset` (in-process single-file: 1 probe + 1 PUT — deliberately *qualifies* DDR-222's wall: the crash class is the mass sweep, not one fetch; probe doubles as the guard against re-uploading what the pull just wrote) and `requestFastPull` (reference-bearing file lands → debounced missing-only pull, because the reference already arrived over the live doc lane). Sweep and poll survive as reconcilers only. **Rejected hub→peer "asset arrived" WS notification explicitly as "the right long-term shape" cut for wire-change cost — a scope-cut, not a principle.** **REVISITABLE — this is the DDR the redesign is most invited to subsume** with event-driven push (which would also delete the probe-guard heuristics and the watcher-gap class).

**DDR-054 — Linked-mode trust model (2026-05-27).** The founding trust document. Linked mode promotes a remote network actor (hub operator / MITM) to a writer with local-user privilege; the adversarial pass composed that with the then-CSP-less same-origin iframe into CRITICAL F1 (hub-pushed JSX → transpiled → executed → `/_api/*`, LAN, IMDS, prompt-injection into adjacent Claude sessions). Pinned: **the hub is semi-trusted** — it may read/write synced state *by design*, but everything it supplies is untrusted input to the local filesystem, and the mitigations are structural: per-machine 0600 token as the consent boundary; CI env kills sync; symlink-safe `O_EXCL` atomic writes; size caps mirroring HTTP-layer caps; loopback-only plaintext; path containment; `__proto__` reviver; **per-machine trust like `known_hosts`, never a committable allowlist** (a committed allowlist is a trust-laundering primitive — a PR adds the URL and its own permission). Awareness fields sanitized at one chokepoint; presence is a named side-channel the operator sees. **IMMUTABLE** — the ground truth lists it verbatim as a hard constraint.

**DDR-115 — Runtime-state taxonomy (2026-06-18).** One canonical VERSIONED vs IGNORED split: canvases + `.meta.json` + `.annotations.svg` + `system/**` + `config.json` + `assets/**` (incl. `.photo.json` sidecars) are content; `_*` runtime (camera, `_state/`, `_comments/`, `_history/`, `_server.json`, …) is per-machine and never travels via git. Camera split out of meta (`_canvas-state/<slug>.view.json`) so pan/zoom never dirties a tracked file; comments are hub-sync-only (versioning them would duplicate the transport); annotations flipped to versioned. **Taxonomy IMMUTABLE; the 4–5 physical copies of it are implementation debt** the redesign should collapse to one source with tripwires (the file-membership pair already has one; `.gitignore`/`gitignore-block` still don't).

**DDR-060 — TSX-only broke HTML-centric sync (2026-05-28).** Two decisions nine days apart collided: Phase 3.6 made `.tsx` the only format; DDR-054 §2b made sync refuse `.tsx` — so the headline sync feature silently synced *nothing* for every real project (discovery returned `[]`, no error). Decisions: acknowledge in writing; fix = make `.tsx` syncable safely (CSP + sandboxed segregated origin FIRST), never resurrect `.html`, never "just remove the guard"; until then, fix the lie not the lock (loud zero-syncable banner). **SUPERSEDED in effect** (remediation shipped as 9.1-A/B → DDR-063 → 079); keep as the canonical trap: a format/scope migration can turn a sibling subsystem into a silent no-op, and silence was the real defect.

**DDR-063 — Canvas-origin split default-ON; tsx sync opt-in; F1 accepted at MEDIUM (2026-05-29).** The F1 containment (segregated canvas origin: strict CSP, route allowlist, iframe sandbox) flipped default-on as pure protection; residuals fixed (`%2f` traversal, WebRTC lockout, allowlist sanitizer rewrite). **The two-locks coupling is the immutable core: a synced `.tsx` without the active sandbox re-opens CRITICAL F1 — never decouple.** The per-canvas opt-in default half is SUPERSEDED by 072→079.

**DDR-072 — Project-level `syncTsx` opt-in.** **SUPERSEDED by DDR-079** (default flipped). Still-standing parts: the field, per-canvas `syncable` override always wins, Lock-2 coupling, and the trust reasoning (a committed flag can't self-activate — the per-machine token is the consent boundary).

**DDR-079 — TSX sync default-ON (2026-06-02).** Default-off bit three times in one dogfood session ("teammate sees nothing", `--adopt` silently no-ops, `git restore` wipes the flag — hence absence-means-on, restore-proof). The trade is explicit: accept the bounded WebRTC/self-nav residual on every synced canvas of a *linked* project in exchange for sync that works, made **safe-by-visibility** (loud boot banner, status advisory, link flags) not safe-by-default-off. **Settled — do not re-litigate polarity**; Lock-2 coupling untouched and IMMUTABLE.

**DDR-088 — Canvas media vocabulary + asset write surface (2026-06-03).** First binary write route reachable from the untrusted canvas origin, so **every cap is the trust mitigation, not optional**: magic-byte sniff (declared type never trusted; SVG matches nothing → 415), 10 MB per-file + 16 MB body + 256 MB session budget (content-addressing dedupes identical bytes only — it is a storage optimization, NOT a quota), content-addressed names, containment assert, anchored single-segment href regex as the traversal guard, link chips client-only (zero server egress — no unfurl SSRF), and **the two-allowlist rule**: a canvas-reachable route must be in BOTH `CANVAS_SAFE_API` and the canvas server's `routes` map, a privileged route in NEITHER, guarded by tests. **IMMUTABLE.**

**feature-sync-file-plane (Plane B, 2026-08-14; kg `sync-two-plane-manifest-architecture`).** Membership-by-canvas-name lost 103 files on a fresh link; every fix added a lane; "the growth is the bug." Decision: two planes, one predicate — Plane A stays per-canvas CRDT; Plane B is ONE manifest-driven file plane for everything else, membership by a single **positively-enumerated, default-closed classifier** shared studio↔hub (classes: canvas-owned→plane A only, inert-media, companion-text, code-module→owner gate, never→config.json + runtime state + everything unclassified). Receiver re-classifies locally (hub `class` is a hint, never authority); LWW conflicts quarantine the loser in `_trash/`, never silent loss; deletion does NOT propagate in v1 (vanished manifest entry ≠ "delete yours" — the branch-switch-mass-delete hazard dodged structurally); `restrictImportsTo` made unconditional on desktop as the code-module condition. Shipped **flag-OFF** (`linkedHub.syncFiles`); real-corpus acceptance 216/216 byte-for-byte; parity condition for the flip already met live (Nález C). **REVISITABLE at the top level — the redesign must decide whether Plane B survives as a separate lane or becomes THE file transport (its own stated intent: "the LAST lane", subsuming the asset lanes)** — but the classifier discipline, receiver-re-validation, quarantine posture, and the F1–F6 flip gate (below) are binding either way.

## 2. HOW SEVEN LANES HAPPENED — the forces, decision by decision

The sprawl is not one bad decision; it is **each lane being the locally-cheapest fix to a real, usually live-observed failure, under two standing walls** (the DDR-193 containment invariant and the DDR-217 fact that git could not be the transport) — with the "right long-term shape" repeatedly deferred as a scope-cut.

| Lane | Added by | Pressure that created it |
|---|---|---|
| 1. CRDT doc lanes | DDR-052 (transport) + DDR-064 (one doc) + DDR-110 (live overlay is the product) + 060→063→079 (tsx bodies admitted through the security gate) | Live multiplayer is the headline; the two-doc side-channel raced (observed live) |
| 2. Asset push sweep | DDR-217 (+ addendum's second class) | Cloud rendered grey boxes — doc lanes carry only text; git-pull structurally impossible (seed strips credentials; histories deliberately separate per Phase-27 D2/DDR-198); cell can't reach a NAT'd desktop; binary-in-Yjs rejected on merits |
| 3. Fast-lane push | DDR-225 | Minutes-level latency of debounce→spawn→full-walk — which only exists because DDR-222 had to exile the sweep to a child after it segfaulted Bun beside the editor |
| 4. Asset pull | v0.60.4 (ground truth §2) + DDR-225's `requestFastPull` | Downward had NO lane at all: a picture dropped in the browser never reached desktop; DDR-223 showed annotation strokes carry `assets/<sha8>` refs whose bytes must follow |
| 5. File plane (flag-OFF) | feature-sync-file-plane / kg 2026-08-14 debate | 103 files lost on fresh link — per-file-class lane growth was itself diagnosed as the bug; designed to be the LAST lane and subsume 2+4, but shipped dark, so today it sits BESIDE them (duplicate jurisdiction, hence the fast-push probe-guard against its own echo) |
| 6. Cell bucket mirror | DDR-195 §2 (content-addressed R2) + DDR-198 §6 (sweep from checkout) + DDR-224 (every door mirrors) | DDR-193: container disk is ephemeral — durability requires R2 + rehydrate; the mirror then needed its own consistency (probe "present = both", boot sweeps, retry) |
| 7. Git autocommit + rehydrate/backup | DDR-195 §3 + DDR-198 + DDR-199 durability spike | A headless cell has no human committer — no commits means the only record is current bytes; checkout must ride the same backup generation as documents |

**The two-architecture split** (desktop per-canvas agent vs cell shared-doc): DDR-064 built shared-doc and shipped it OFF out of caution; DDR-213 turned it ON for cells only (loopback pairing). Nobody ever decided to run two architectures — it is an unfinished cutover, and it is why the eraser had to be fixed twice and why every future lane semantic costs double.

**Why push is scheduler-driven:** DDR-217 accepted boot-time sweep as v1 ("a watcher hook is a follow-up if it ever bites" — it bit); DDR-225 rejected hub→peer WS notify purely on wire-change cost. Meanwhile the live doc lane already delivers events in milliseconds — the reference-triggered pull is a workaround that exploits exactly that fact. The event-push shape has been named "right" twice and cut twice; it has never been rejected on principle.

**Why three reconcilers:** each transport got its own repair loop (sweep for push, poll for pull/file-plane, rehydrate for boot) because no component owns "is file X delivered everywhere" — the DDR-214 amendment even documents that the missing primitive is a confirmed round trip ledger, rejected then as premature, whose revisit trigger has since fired.

## 3. TRAPS — ranked; each with the structural property that makes it impossible

1. **The cold-start eraser (shipped THREE times: DDR-076 fresh-hub zeroed 73 canvases; DDR-102 stale peer overwrote a day of work; DDR-223 annotations eraser).** Emptiness or staleness treated as authority. → Properties: **one pure cold-start decision table with ONE apply-site** used by every architecture; **per-lane edit stamps** for every independently-editable lane (a lane without a stamp WILL regress to a proxy winner); **semantic emptiness** per format (72-byte wrapper ≠ content; `''` checks are not guards); *unstamped emptiness never beats content*; **fail-closed snapshot-before-overwrite** (if the loser's snapshot didn't land, refuse the overwrite — DDR-102 §3).
2. **Same bug, fixed twice, because two sync architectures exist** (agent vs shared-doc; the eraser needed both fixed; the decision tables are shared but appliers are 2×). → Property: **one sync architecture** — finish the DDR-064 cutover / take DDR-213's C1; until then, shared tables AND shared appliers, with any unavoidable twin pinned byte-equal by a drift test (DDR-198 rule).
3. **The watcher gap: bytes arrive, nobody is told** (container `fs.watch` misses atomic tmp+rename; DDR-213 closed it for projection writes only; hub-side asset PUTs still have no announce — the ground truth's prime suspect for "transport OK, viditelnost NE"). → Property: **every write site announces its own write** (server-push event carrying `{file, hash}` on the already-open WS); *inference from filesystem watchers is never the delivery mechanism*, and "delivered" includes "UI healed" (DDR-224's asset-heal mode is the consumer).
4. **Structurally silent failure** (`sweepNew` failures in `result.failed` that no caller read — zero log lines of bucket drift; the 0.60.4 changeset selling flag-OFF behavior as live; DDR-060's silent `[]` discovery; DDR-199's env vars that "look configured, do nothing"). → Property: **no best-effort path without a report** — every lane's failure is loud, retried, and queryable; a feature that is off must say so; boot health states facts (`/health` pattern).
5. **Two stores with independent truth** (bucket-only GET 404ing a file the same process served to browsers; checkout-only files lost to a rollout restart; "present = both" probe semantics; a week of drift bugs). → Property: **one store of serving truth** (the checkout — DDR-224 made it so); the bucket is pure write-behind durability with **every write door mirroring** and no serving/probe semantics of its own.
6. **Status lies** (monitor born online; first-match aggregate; counters that only rise; `remoteGap` enumerating the files that just arrived; "83/83 syncing" pre-handshake). → Property: **one pure presentation rule read by every surface, fail-closed** — `synced` is a positive assertion, unknown payloads render pessimistic, **refusal outranks unreachability outranks any count**; plus the per-file delivery receipt ("on hub / at peers / UI healed") that DDR-214 deferred and the ground truth now demands.
7. **Scheduler-driven delivery + per-lane heuristics** (20 s poll, debounce ladders, probe-guards against your own echo, fast-lane special cases). → Property: **event-driven push as the primary path** (kills the poll, the watcher gap, and the echo heuristics at once — DDR-225 rejected it only as a scope-cut); polls/sweeps demoted to idempotent reconcilers.
8. **Membership by name, not by classifier** (a file traveled iff a canvas claimed it: 103 lost files; `.photo.json`/`.audio.json`/`.srt` laneless until a real-tree audit; DDR-060's format migration turning discovery into `[]`). → Property: **one positive, default-closed classifier over the whole tree** decides membership for everything non-CRDT; acceptance = **file-for-file tree parity on a REAL project's tree** (fixtures never contain the long tail).
9. **Taxonomy copy drift** (DDR-115 lists drifted once; now 4–5 copies, only one pair tripwired). → Property: one physical classifier source (or every copy pinned by a parity test that imports both — the doc-name precedent); adding a `_*` path must be a one-place change.
10. **Green in dev, broken in the artifact/container** (sweep spawn with no `MAUDE_BUN_PATH` in the .app; signal handler eating the final commit; missing CA bundle; `envVars` replacing image ENV; the blank-window client bundle). → Property: **gates run against the built artifact and the real container** (`check-bundle-completeness --smoke`, boot-the-image tests); "the tests pass" is the beginning of verification (DDR-198).
11. **Mass work in-process beside the editor** (full sweep segfaulted Bun ×3 and took the editor with it). → Property: full-walk/mass-hash work stays out-of-process (or is eliminated by the event-driven design); a dead worker is a reported failure, **never an invisible in-process fallback**; single-file fetches are exempt (DDR-225's qualification).
12. **Self-echo loops** (fast-push re-uploading what the pull just wrote; two writers producing the same projection bytes; the constant-wrapper self-echo residual). → Property: origin tagging + content-hash echo guards by construction; a single delivery ledger removes the need for per-lane probe heuristics; idempotence (409/skip) as the universal backstop — it "saved every force-move and retry this week".
13. **Auth-burst self-DoS** (83 sockets × 2 peers pinned the rate bucket forever; infinite per-socket retries; resync re-auths every document). → Property: one multiplexed socket; valid/invalid buckets split; permanent-class rejections destroy the retrier; controls that re-auth N documents carry cooldowns.

## 4. SECURITY CONSTRAINTS ANY FILE-TRANSPORT REDESIGN MUST SATISFY

**From DDR-054 and its line (063/079/088/193/195/198/213/217/222):**

- **The hub is semi-trusted / untrusted-to-peers.** It may read and write synced state *by design*, but: everything hub-supplied is untrusted input; **the receiver re-validates every path and every byte** (shape gates, containment, local re-classification — a hub-sent `class`/name/mtime is a hint, never authority; naming authority is never handed to the hub). The hub may refuse to serve; it must never be able to **substitute** — content-addressed pulls verify bytes hash to their name or are refused.
- **Content-addressed upload names** for the content-addressed class (idempotent push, verifiable pull, immutable cache semantics); `assets/` never GC'd; **no presigned URLs in canvas content, ever** (bearer credential inside the least-trusted content + breaks `img-src 'self'`); media rides the authenticated proxy.
- **Consent boundary = the per-machine 0600 token**, never a committed file (committable allowlists are trust-laundering primitives); explicit trust prompt per new hub; sync disabled in CI; plaintext WS loopback-only.
- **The two-locks coupling:** hub-pushed executable content renders only inside the segregated canvas origin (strict CSP incl. `connect-src`/`img-src`, iframe sandbox); never decouple sync admission from the sandbox — that re-opens CRITICAL F1 (RCE + trifecta prompt-injection into adjacent Claude sessions). Synced content is marked untrusted (`_untrusted/INDEX.json` + managed `.claudeignore`) on surfaces where an agent reads the tree.
- **The two-allowlist rule (DDR-088):** any route reachable from the canvas origin is in BOTH `CANVAS_SAFE_API` and the canvas server's `routes` map; privileged routes (file-write, export, config, **resync**) in NEITHER; both halves pinned by tests. Amplification-capable controls are main-origin-only (DDR-222 D7).
- **Write-surface discipline on every door:** anchored-regex key shapes (no `..`, bounded depth/charset/length), realpath containment that **writes to the resolved parent** (the TOCTOU lesson), `lstat`-refuse leaf symlinks on READ routes (they follow; write routes replace — the F5 asymmetry), **binary-extension allowlist as the backstop against data→code writes** (never `.tsx`/`.css`/`.json` through an asset door), magic-byte sniffing where type matters (SVG never enters through an image route), streaming with per-file caps + session/aggregate byte budgets, rate-limited probes (no free existence oracle).
- **DDR-193 containment:** no tenant TSX evaluated on vendor compute — the test is *evaluation*, not serving bytes (DDR-209); prune-then-assert; withheld = 404; boot-assert + CI gate; a redesign feature needing vendor-side evaluation has Direction B as a hard prerequisite.
- **DDR-213 pairing conditions:** loopback-only, exactly one committer, minted store token (never `HUB_SECRET`); DDR-195/198 history rules: append-only, author=human/committer=bot, no force-push anywhere, sanitized identity strings.
- **DDR-115 taxonomy:** runtime state (`_*`, camera, comments store, `_history/`, `_sync.json`, …) never travels on any file lane; `config.json` never travels.
- **Owner gate on the code-module class**; `restrictImportsTo: designRoot` unconditional on every canvas build site.
- **Posture rules:** fail-closed cold start (snapshot-before-overwrite, refuse on snapshot failure); idempotent push/pull (temp+rename, HEAD/probe-skip, 409/skip); loud failure logging; credentials in 0600 files never argv; fail-closed status rendering with refusal outranking everything.

**The F1–F6 flag-flip gate** (binding on `linkedHub.syncFiles` default-ON, and on any successor file plane — `/flow:validate-security` re-run as a HARD gate; parity precondition already met live):

- **F1 (load-bearing):** hub-synced `.md`/`.css`/(owner-)code lands under `.design/system/**`, which design agents read as authoritative spec → indirect prompt-injection / lethal trifecta (untrusted content + private data + outbound in one agent loop). Required: treat hub-synced docs as **delimited untrusted DATA, never spec**; never co-locate hub-synced content with credential access + outbound in one agent context. Structural, not prompt tuning.
