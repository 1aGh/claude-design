# DDR-141: Brand assets as Tier-0 prior + `dsFidelity` enforcement gate — completing DDR-127 for logo / iconography / components

- **Date:** 2026-07-02
- **Status:** Accepted (implemented with this change)
- **Tags:** design, design-system, pattern-priors, brand-assets, logo, iconography, enforcement, design-system-keeper, brand-critic, opt-out, consumer-side
- **Related:** [DDR-127](./DDR-127-showcase-grounded-canvas-generation.md) (showcase Tier-0 prior — this record extends the same pattern to brand assets AND revises its "nudge, never gate" severity stance behind an opt-in knob), [DDR-010](./DDR-010-design-system-keeper-agent.md) (keeper audit this extends with Pass A.7), [DDR-073](./DDR-073-aesthetic-ambition-axis.md) (the `opt_out_scope` default axis `dsFidelity` composes with), [DDR-061](./DDR-061-sidecar-cache-monitor-background-orchestration.md) (DS-context cache pack extended), [DDR-043](./DDR-043-bias-free-design-plugin-templates.md) (unaffected — consumer-side only, no template edits). RCA: [`.ai/logs/rca/issue-ds-awareness-hardening.md`](../logs/rca/issue-ds-awareness-hardening.md).

## Context

User report (2026-07-02): canvases generated by `/design:new` / `/design:edit` ignore the DS's stored logo, invent their own icons and components, and don't adopt showcase layouts — despite `config.json` declaring a default DS. The demanded contract: **DS-first "za každou cenu"** — generation must use the DS's canonical specimens wherever they exist; inventing is legitimate only where no specimen exists; a user-declared `--ds=<name>` or free-use opt-out must keep working.

The RCA (three-seat hypothesis debate, DDR-130 relay tier, converged without cross-challenge) found a **three-layer composite cause**:

1. **Brand-asset blindness.** The DS predictably ships `preview/logo.*` + `preview/iconography.*` (`_MAPPING.md`), yet no generation-direction layer ever reads or names them: `/design:new` step 5a globs only `components-*.tsx` + `ui_kits-*-showcase.tsx`; the DDR-061 cache pack is `{classNames, tokenNames, libExports}`; the keeper has no asset pass; the ux-patterns payload excludes visual identity. Worse, envelope directive 10 ("Brand mark featured at human scale") *orders* a logo while no path to one is delivered — the pipeline invites invention. The hole is double-sealed: the `HAS_LOGO` routing grep (`logos?/|wordmark|brand-mark`) can't see an invented inline `<svg>` mark, so `brand-critic` never routes; and step 9.6 reroutes the invented mark to `draw-agent`, which *rebuilds the invention* instead of substituting the canonical asset.
2. **Advisory enforcement.** Keeper findings are warnings (blocker only at ≥5 token / ≥3 pattern stacking, with `icon` and `card` on the Pass-A skip-list so they never count); Pass A.6 never self-promotes; the auto-fix loop consumes **blockers only** — warnings survive all iterations. DDR-127 explicitly rejected a hard gate ("strong default, enforced as a visible nudge, not a gate"), which is the exact opposite of the user's contract.
3. **New-path delivery gap.** The envelope carries priors as paths + class-name strings (never file content — the edit path Reads showcase content per DDR-127, the new path does not), and the envelope's "Read the DS" instruction pointed at `system/README.md`, which does not exist (real files are `system/<ds>/README.md`). Downstream, the `frontend-design` skill is contractually invent-first ("NEVER converge", "avoid generic fonts") — without inlined content + an explicit DS-pin it designs *against* the DS.

## Decision

Two-sided fix — **delivery** (so reuse happens on the first pass) plus an **opt-in gate** (so invention can't silently ship) — mirroring DDR-127's shape and completing its coverage:

1. **Brand assets become a Tier-0 prior alongside the showcase.** `/design:new` step 5a additionally resolves `preview/logo.*`, `preview/iconography.*`, and the DS `assets/` tree; step 5b's envelope gains a `### Brand assets (canonical — reuse, don't invent)` subsection whose logo entry is **inlined content** (the specimen's mark markup), not just a path, and directive 10 now points at that slot. `/design:edit` pre-loads the logo/iconography specimens on brand-touching and add-surface edits.
2. **New-path delivery parity.** The orchestrator **Reads and inlines content** of the platform showcase (and the brand-asset specimens) into the envelope before invoking generation — same as the edit path since DDR-127. The dead `system/README.md` reference is fixed to `system/{ds}/README.md`. The envelope gains an explicit **DS-pin block** that overrides the generator skill's invent-first contract whenever a DS is in effect: fonts/colors/icons/logo/shell are pinned; invention is legitimate only for missing specimens.
3. **DDR-061 cache pack extended** with `logoSpecimenPath` + `assetNames` so repeat runs know the brand inventory without re-globbing.
4. **`design-system-keeper` gains Pass A.7 (brand-asset reuse)** — flags an inline `<svg>` mark / hand-rolled icon family when the DS ships `logo.*` / `iconography.*`. `icon` and `card` leave the Pass-A skip-list (they are compositional shapes, not utilities). The keeper now receives `opt_out_scope` + `ds_fidelity` and applies the severity matrix below.
5. **New config knob `dsFidelity: "advisory" | "strict"`** (`.design/config.json`, default `advisory` = zero regression). `strict` is the user's "za každou cenu": reinventing a specimen the DS ships (logo, icon set, component shape, product shell) is a **blocker** the auto-fix loop must clear — a scoped revision of DDR-127's nudge-only stance for opted-in projects.
6. **One axis, not two competing switches.** `dsFidelity` composes with the existing `opt_out_scope` axis: an explicit per-canvas `--opt-out=full` **wins over `strict`** (deliberate free-use beats project policy); `--opt-out=aesthetic` relaxes only what that scope already relaxes. Resolution order stays: canvas flag → `.meta.json` → `aestheticAmbition` default — `dsFidelity` only decides the *severity* of reuse findings at the resolved scope. A11y stays independent of both.
7. **Routing + critic fixes.** `HAS_LOGO` detection now also counts a sizeable inline `<svg>` mark and the presence of DS brand assets; `brand-critic` joins the `/design:new` default panel whenever the DS ships brand assets, reads DS-aware paths (`system/<ds>/preview/logo.*`, `system/<ds>/assets/` — not the hardcoded `<project>`), and gains a **canonical-mark identity** check (non-canonical mark when the DS ships one → warning in advisory, blocker in strict). Step 9.6 / 4.6 check the DS for a canonical mark FIRST and substitute it — `draw-agent` is for genuinely new art only.

## Consequences

- **Tier-0 priors are now two-headed:** placement (showcase, DDR-127) + identity (brand assets, this DDR). Tier 1 = existing same-DS canvases, Tier 2 = component specimens — unchanged.
- **DDR-127's "nudge, never gate" stance is now conditional**, not reversed: `advisory` keeps it verbatim; `strict` is an explicit, user-owned reversal. Pass A.6 shell reinvention promotes to blocker only under `strict`.
- **Downstream projects see no behavior change until they opt in** — absent `dsFidelity` = `advisory`. What DOES change by default: the envelope now carries brand assets + inlined showcase content (first-pass reuse improves), brand-critic routes on `/design:new` when brand assets exist, and keeper warnings get more precise. All additive.
- The design plugin stays project-agnostic and templates stay bias-free (DDR-043) — no template carries a brand value; the mechanism only *transports* whatever the project's DS ships.

## Alternatives considered

- **Delivery only (feed the assets, keep everything advisory).** Rejected as sole fix — that is exactly the DDR-127 trap the ticket demonstrates: the showcase was delivered (as a path) and the complaint persisted. An invent-first generator plus a warnings-only audit lets drift ship.
- **Gate only (hard blockers, no envelope change).** Rejected — catches invention *after* it happens, costing a fix iteration per asset every run. The user wants first-pass reuse; the gate is the backstop, not the mechanism.
- **Always-strict (no knob).** Rejected — DDR-127's false-positive argument stands: shell/asset detection is heuristic, and a hard block on fuzzy signals would fight legitimate novel surfaces. Strictness must be a project-level choice with a per-canvas escape hatch.
- **A separate `--use-ds-assets` flag per invocation.** Rejected — a second per-call switch competing with `--opt-out` on the same "how much does the DS bind" axis; config-level policy + the existing scope axis covers it with less surface.
