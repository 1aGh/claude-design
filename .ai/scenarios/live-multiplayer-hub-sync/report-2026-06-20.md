## F4 — observer update is now an in-place hot-swap (no reload, no presence blink) ✅

**Method (deterministic, origin-independent):** opened `SyncTest` on B via `/_canvas-shell.html`, planted a `window.__F4_SENTINEL` that a `location.reload()` would wipe but a hot-swap preserves. Edited `SyncTest.tsx`'s `<h1>` on **A**, let it sync cross-hub to **B**, then read the sentinel.

**Result:**
- B's content updated (`FLICKER PROBE 2` → `SEAMLESS HOTSWAP OK`) in **~1 s**.
- `window.__F4_SENTINEL` **survived** (`ALIVE@…`) → **the iframe was NOT reloaded** → the canvas module was hot-swapped in place. `window.__maudeCanvasRuntime` stayed registered (same realm).
- **Repeatability:** a second synced edit (`shared canvas body` → `HOTSWAP ROUND 2 ✦`) landed in ~2 s and **both** sentinels (round 1 + round 2) survived — proving the iframe is never reloaded across consecutive hot-swaps.

Since the canvas iframe is never torn down, the `CollabProvider` is never reload-remounted, and — because the collab session is now a module-level, refcounted singleton (`use-collab.tsx`) that survives even the React subtree remount — the awareness socket never drops. The 2026-06-19 blink (avatars gone → back, `evidence/05→06→07`) cannot occur. Confirmed by the `collab-session-survival.test.tsx` unit (same doc + Awareness `clientID` across a remount; socket constructed once).

**Code:** `_shell.html` now routes any `mode:'module'` change to `softReload()` (hot-swap) whenever the runtime is mounted — covering cross-peer **synced** writes, not just agent edits; `mode:'hard'` (`_lib`) still full-reloads.

## F1 — concurrent cold-seed duplication is detected + auto-collapsed ✅

**Method (reproduces the real race):** created a byte-identical fresh `ColdSeed.tsx` (single `export default`) in **both** repos under a slug the hub had never seen (empty hub doc: `ui-coldseed`), then **restarted both servers simultaneously** so each cold-seeds the same empty hub doc at once.

**Result:**
- The race genuinely fired — `server-a.log`: `[sync/ui-coldseed] concurrent cold-seed duplication detected — collapsed to one copy (F1).` (i.e. the Y.Text **did** double from the two simultaneous seeds, and the elected single-writer repair collapsed it).
- Converged state on **both** disks: `export default` = **1**, `function ColdSeed` = **1**, 721 bytes, byte-identical.
- Canvas **builds** on both servers (`HTTP 200`, not 500) and **renders** ("COLD SEED RACE", `step-3`) — the 2026-06-19 symptom (two `export default` → build 500 → blank) is gone.

**Code:** the seed now claims a `syncMeta.seededBy` clientID marker (Y.Map LWW → one elected writer on every peer); on a remote update inside a bounded window that writer re-applies the canonical body, whose diff deletes the trailing duplicate (CRDT-correct, idempotent). `decideColdStart` also gained a `recover-seed-dup` row so a peer booting against an already-doubled hub self-heals. Deterministically covered by `sync-cold-seed-dedup.test.ts` (two agents, simultaneous identical seed → one copy).

## Second pass (same day) — two-peer presence stress: found + fixed a regression

A follow-up run with **two browser peers** (one per server) stress-tested exactly the two things the F4 hot-swap touches: avatar accumulation and a stuck "editing" badge.

### F5 — phantom "self" avatars pile up on every hot-swap (regression in the F4 fix) ⚠️→✅ FIXED
Editing repeatedly made the peer avatar count climb monotonically (1→2→3→…→8) instead of staying flat. Isolated it: with the other peer **closed**, a peer editing its **own** repo still accumulated phantom avatars — so each hot-swap was minting a **new collab session (new Yjs clientID)** and the prior clientID's awareness lingered on the hub until the ~30 s timeout, rendering as a ghost of *yourself*.

**Root cause:** the first version of the `use-collab` session registry was a **module-level** `const SESSIONS = new Map()`. But `softReload` hot-swaps by **re-importing the canvas bundle with a `?v=` cache-buster**, and `use-collab` is **inlined** into that per-canvas bundle — so every hot-swap re-evaluates a **fresh module with a fresh, empty map**. The session-survival cache was being wiped by the very re-import it was meant to survive. Instrumented + confirmed live: the `clientID` changed on each hot-swap while `sessionCount` stayed 1.

**Fix:** anchor the registry on **`window`** (resolved lazily — `window.__maudeCollabSessions`), which persists across the cache-busted re-import. Mirrors the existing window-anchored undo stacks / activity seed. Pinned by a new unit assertion (`collab-session-survival.test.tsx`).

**Re-verified live (debug-free build):**
- Brand-new room, peer alone → **0 avatars**, stable across 5 edits.
- `clientID` now **stable** across every hot-swap (`sessionCount` 1). A stable clientID across a swap *also* re-confirms F4: a full reload would have wiped the window registry too, so survival proves it was a hot-swap.
- Transient stale states **GC to 0** (no permanent leak; the old monotonic growth is gone).

### "Editing" activity badge clears (does NOT stick) ✅
The artboard activity rim (`[class*=dc-activity]`, "editing — <file>") appeared on every synced change (count 3 during) and **cleared within ~5 s** of the edit settling (count 0) on every iteration — never stuck.
