# DDR-089 — Sticky sharp bottom-right corner: live-render-only

**Date:** 2026-06-04  
**Status:** accepted  
**Feature:** annotation-tooling-polish (item 1)

## Decision

Change `StrokeNode`'s sticky body from `<rect rx ry>` to a `<path>` with
TL/TR/BL rounded at `cornerRadius` and **BR a square corner**, but **keep the
persisted form (`strokeToSvgEl`) as `<rect>`** — i.e., the sharp corner is a
live-render-only presentation detail.

## Context

FigJam sticky notes have a characteristic sharp bottom-right corner (the
"dog-ear" silhouette). Replicating it required replacing the uniform-radius
`<rect>` in `StrokeNode` with a `<path>` generated by `stickyCornerPath()`.

Two options existed:
- **A) Render + persist**: emit a `<path>` in `strokeToSvgEl`, update `svgToStrokes`
  to parse it back, add a new frozen fixture for the byte-identical canary.
- **B) Render-only**: keep `<rect>` in `strokeToSvgEl`; only `StrokeNode` (React
  live view) uses the `<path>`.

## Rationale for B

Every interactive user view (open canvas, reload, collab peer) re-renders
through `StrokeNode`, so the sharp corner appears in **all user-visible
contexts**. The only divergence is raw persisted-SVG consumed without the React
renderer — the sanitizer fallback path and `.svg` export via `strokesToSvg`.

Option A would have required: a `<path>` body in the serializer, `data-x/y/w/h`
on the `<g>` wrapper for the parser to recover geometry, a reworked `svgToStrokes`
branch, and a new frozen fixture. All of this adds canary risk for a gap that
only manifests in the SVG-export edge case.

## Consequences

- **SVG export fidelity gap**: a sticky exported as a raw `.svg` has uniform
  rounded corners, not the sharp BR. Flagged as a known minor gap; a follow-up
  can address it if `.svg` export becomes a first-class use-case.
- Zero canary / sanitizer / parse impact: `strokeToSvgEl` unchanged.
