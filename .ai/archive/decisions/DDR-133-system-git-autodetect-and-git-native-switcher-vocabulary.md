- **Status:** Accepted (implemented — `.ai/plans/feature-git-switcher-fast-and-trustworthy.md`)
- **Tags:** dev-server, git, isomorphic-git, system-git, performance, network, timeout, vocabulary, native-only, security
- **Related:** [DDR-107](./DDR-107-git-engine-isomorphic-git.md) (this activates its deferred detect-and-prefer-system-git end-state), [DDR-131](./DDR-131-remote-draft-checkout-and-refresh-model.md) (the transport classifier this composes with — `classifyRemoteUrl` / `isTrustedTokenHost` / `HARDENED_REMOTE_FLAGS`), [DDR-132](./DDR-132-github-identity-swr-disk-cache.md) (the probe TTL/dedupe wrapper these timeouts live inside), [DDR-110](./DDR-110-three-lane-collaboration-model.md) + [DDR-119](./DDR-119-native-owns-the-workspace-web-is-a-repo-bound-companion.md) (the plain-language "Shared version / draft" vocabulary this **supersedes for the switcher surface only**), [DDR-108](./DDR-108-github-token-loopback-bridge.md) (token loopback bridge — unchanged). ## Context

Six user-reported problems with the native version switcher on real developer repos shared one root cause and one product-vocabulary mismatch.

**Root cause (issues "can't fetch / 30 s auth stall / dropdown disappears"):** the git engine is isomorphic-git by default (DDR-107); native git was opt-in only (`MAUDE_USE_SYSTEM_GIT=1`, which the desktop never set). Branch *listing* was already disk-only/instant, but the two *network* paths — `gitFetchRemote` (Refresh) and `remoteAheadBehind` (the unattended `status?remote=1` ahead/behind probe) — ran pure-JS fetches **with no timeout**. On a bigger repo the fetch stalled (client gave up at 45 s → "Refresh timed out") and the startup probe stalled the perceived GitHub-auth readiness ~30 s. A developer's terminal does `git fetch` / `git branch --remote` instantly; the app didn't, because it wasn't using their git.

**Repo discovery (issue "only one repo in Pull-a-local-copy"):** `listUserRepos` queried `/user/repos?affiliation=owner,collaborator` — omitting `organization_member`, so every repo reachable only through org/team membership was invisible — and fetched a single un-paginated page.

**Vocabulary (issues "what's this button / can't find main"):** the switcher rendered `main`/`master` as "Shared version / what everyone sees" and branches as "drafts" — a deliberate plain-language layer for the non-technical persona (DDR-110/119). The reporting user is a developer; the abstraction actively obscured `main` and the merge action. Resolved by a `/flow:plan` user decision: **go fully git-native for this surface.**

## Decision

1. **Auto-detect-and-prefer system git for the NETWORK paths (DDR-107 end-state).** A memoized `systemGitAvailable()` probe (`git --version`, one spawn per process — the sidecar respawns per repo, so per-process is correct) gates `gitFetchRemote` and `remoteAheadBehind`: when a `git` binary is present the native engine runs the fetch (instant, and it uses the user's own credential helper / SSH agent — so a signed-in token is no longer even required for a developer). The **local-only** paths (status / commit / list / checkout / log / diff) stay on the zero-dependency iso engine, unchanged — the blast radius is exactly the two slow network ops. `MAUDE_USE_SYSTEM_GIT=1` still forces system git everywhere (legacy override); `MAUDE_NO_SYSTEM_GIT=1` opts the network paths back to pure iso (escape hatch + test determinism).

2. **Token/host policy is engine-independent.** The DDR-131 gate is unchanged and still runs FIRST: `classifyRemoteUrl` refuses `ext::`/`fd::`/`file://`/unknown transports before any spawn; the PAT attaches only to a `github.com` HTTPS host (`isTrustedTokenHost`); `HARDENED_REMOTE_FLAGS` (`protocol.ext/fd.allow=never`) ride every fetch. The engine probe only decides **which engine runs an already-vetted op** — it never relaxes the refusal. To keep behavior + the security tests deterministic regardless of whether the host happens to have git, the HTTPS-must-be-github and sign-in-required checks were **hoisted before the engine split** in `gitFetchRemote` (so a non-github HTTPS remote is refused identically on both engines, and the token is never lent to another host on either).

3. **Every network git op is bounded (`withTimeout` / `runGit` SIGKILL).** Fetch ≤ 12 s, probe ≤ 8 s. A fetch timeout returns a typed `{ timedOut: true }` friendly result; a probe timeout **throws** so the DDR-132 wrapper never caches it (the next poll retries; local status is unaffected). The unattended poll can no longer hang the UI.

4. **The switcher never lets the network blank the local list.** The client re-reads `/_api/git/branches` (disk-only, instant) on every popup open and clears any stale error, so a flaky network can't leave the dropdown empty. A Fetch failure renders as a **dismissable in-popup notice** (`.rb-pop-notice`), never the persistent dock-level error, and never replaces the local list. A search miss offers an explicit "Search the remote" (the bounded fetch) instead of a dead-end.

5. **`listUserRepos` adds `organization_member` + paginates** (up to 500 most-recently-updated). Org/team repos now surface in "Pull a local copy".

6. **Git-native vocabulary for the switcher (supersedes DDR-110/119 for THIS surface only).** Branches show their real names; `main`/`master` is "the default branch · what everyone sees"; the fold action is "Merge this branch → main"; sections are "Branch" / "Switch branch" / "Other branches"; Refresh is "Fetch remote branches"; New is "New branch". The **non-switcher** plain verbs (Save version = commit, Publish = push, Get latest = pull) are **untouched** — they remain plain by DDR-110, and the web read-only badge (DDR-119) is unchanged.

## Consequences

- **Good:** a developer's fetch/probe are native-fast and work via their existing credentials; the ~30 s startup stall and the "Refresh timed out / dropdown vanished" failure modes are gone; org repos are discoverable; the labels read in the git terms the user already knows. Zero new dependency; the iso engine remains the no-git fallback, so the DDR-107 zero-setup promise holds for the non-technical persona.
- **Security (defender PASS + adversarial — `.ai/logs/security-reviews/ddr-133-system-git-{defender,attacker}.md`):** the DDR-131 RCE/local-read posture **holds** — `classifyRemoteUrl` runs before the engine branch on every sink, so `ext::`/`fd::`/`file://`/bare-path collapse to `unsafe` pre-spawn and the PAT never leaves `github.com`. **The adversarial pass found one real DDR-133 regression (F1, Medium, FIXED before commit):** the auto-detect made `systemGitAvailable()` default-true, and in the **unattended** `remoteAheadBehindUncached` probe the `!trustedHttp` host-allowlist sat *after* the engine branch — so a poisoned non-github `remote.origin.url` (http) got an unattended `git fetch` = SSRF/presence-beacon. Fix: hoist `if (transport === 'http' && !trustedHttp) return {0,0}` before the engine branch (mirrors `gitFetchRemote`), + a regression test (`remote-ahead-behind-cache.test.ts` "SECURITY (DDR-133 F1)…"). Pre-existing/accepted (not this diff): the unattended probe still allows ssh to a user-configured host (DDR-131-accepted, same as the explicit Refresh — flagged as a warning). Covered by `git-branches.test.ts` SECURITY cases (engine-independent) + the F1 test + DDR-132 probe-cache tests, green under both default and `MAUDE_NO_SYSTEM_GIT=1`.
- **Accepted / scoped:** the backend `gitFoldDraft` edge-case error strings still say "Shared version" (surfaced verbatim by the UI in the fold-into-itself case) — left as a minor follow-up rather than widening the diff into the fold service. `gitPush`/`gitPull` keep their existing engine selection (the DDR-131 follow-up host-allowlist for those token paths remains open). The network timeout bound is not unit-covered (deterministically simulating a hung `git fetch` is flaky/low-value — the DDR-131 precedent that the fetch network path isn't offline-testable applies); verified by code review + manual native dogfood.
- **Verification ceiling:** native-only dock (DDR-119) — the 5-platform `scenario-runner` and the browser canvas-smoke do not exercise the native switcher (it's `native`-gated chrome). Coverage = unit tests (engine matrix + security gate + repo pagination) + the release bundle build + manual native dogfood, consistent with the DDR-131/132 precedent.

## Alternatives considered

- **Adaptive vocabulary (git-native when system git detected, plain otherwise)** — rejected at the `/flow:plan` fork: two UI variants to maintain/test for a single-user-persona benefit; the user chose one clear direction.
- **Keep plain vocab, just append the git name ("Shared version · main")** — rejected by the same fork; the developer wanted the git name to *lead*, not trail.
- **Prefer system git for ALL ops (not just network)** — rejected for blast radius: DDR-107's addendum warns against splitting status/commit/checkout across two untested-in-combination engines; scoping the switch to the two genuinely-slow network paths gets the win without the risk.

## Implementation addendum (final state, 2026-06-30)

What actually shipped went beyond the network-paths-only Decision above, because dogfooding on a **real 306-branch repo** (the reporter's `AI-StudyMate`) exposed the true root cause:

1. **The auto-detect was expanded to the READ paths, not just the network paths.** `dev:desktop` logs showed iso-git's `git.statusMatrix` / `git.listBranches` **crashing** (`error: No obj for <dir>`, caller `git.statusMatrix`) **and** being slow enough to trip the 10 s `Bun.serve` idle window — *that* (not the network probe) is what made the branch list vanish + the dropdown hang. So `systemGitAvailable()` now also gates `gitStatus` / `gitListBranches` / `gitLog` / `gitDiff` / `gitShowFile` / `localUnpushed` / `currentBranchOf`. iso still backs the WRITE paths (commit/checkout/branch/fold/push/pull) unless `MAUDE_USE_SYSTEM_GIT=1`. Measured on the 306-branch repo: status 87 ms / branches 62 ms via system git vs crash + 10 s timeout on iso.
2. **Phantom `origin` branch row** — `git for-each-ref --format=%(refname:short) refs/remotes/origin` collapses the symbolic `refs/remotes/origin/HEAD` to the bare name `origin`, which leaked in as a fake branch. Filtered (`full === DEFAULT_REMOTE` skip).
3. **Engine-aware tokenless-fetch guard** — the first cut hoisted `transport === 'http' && !token → authRequired` ahead of the engine split, which broke tokenless fetch on the system engine (which can use the dev's credential helper, like push/pull do). Corrected to `… && !(await systemGitAvailable())`: iso-without-token → sign-in; system git → credential helper. `noSystemGit()` became a live `process.env` read so a test can scope `MAUDE_NO_SYSTEM_GIT` around the iso-only assertion without leaking.
4. **Verification — DOM-driven desktop-e2e (`desktop-e2e` skill), not just unit tests.** Three native-app scenarios drive the real WKWebView via `data-testid` (added to the switcher + GitPanel): `git-branch-switcher` (list/vocab/no-phantom-origin), `git-lifecycle` (new-branch · switch-branches · commit · push · fetch · merge-to-main · pull, against a real github clone with `MAUDE_USE_SYSTEM_GIT=1` so push/pull/fetch use the dev's credential helper), and `git-switch-repos` (`open_local_project`, retried — the sidecar-respawn is WebDriver-flaky). 12 evidence screenshots. New harness gotchas recorded in the skill (offline-remote fixture, single-branch shallow-clone, plugin-init warn). This supersedes the "manual native dogfood" line in Consequences above.
