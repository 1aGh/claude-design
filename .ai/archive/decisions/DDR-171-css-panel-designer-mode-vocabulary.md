# DDR-171: CSS panel gains a second, Figma-vocabulary "Designer mode" — a conscious, scoped override of DDR-104 §2

**Status:** Accepted — 2026-07-14
**Supersedes:** [DDR-104](./DDR-104-css-panel-ux-model.md) §2 ("Vocabulary = Hybrid… we do not rename properties to human labels") — **for the Designer-mode scope only**. DDR-104's other decisions (value source, curated tier, token-first, the two escape hatches, provenance, canvas-first critic gate) are unchanged and still govern both modes.
**Related:** [DDR-104](./DDR-104-css-panel-ux-model.md) (the panel this extends), `.ai/plans/feature-inspector-controls-designer-mode.md` (the plan implementing this decision), `.ai/plans/archive/feature-inspector-controls-redesign.md` (Phase 1 — the control-library primitives Designer mode reuses).

## Context

DDR-104 deliberately rejected human-label vocabulary translation ("Fill" instead of `background-color`, etc.) after a live user-feedback round on the original raw-CSS-only panel — the reasoning was that a code-backed tool should keep the row honest to the real property name, with friendly section headers carrying the approachability instead.

That reasoning held for a panel used by one audience: people iterating on real TSX who think in CSS. It stops holding once a second audience shows up — a non-technical user who doesn't think in `border-radius` / `box-shadow` / `flex-direction` at all and hits a wall the section headers don't solve. The user asked explicitly for a Figma-vocabulary mode (2026-07-14) after using the shipped Phase-1 control library long enough to feel this gap.

Three independent debate seats (BUILDER, SHIPPER, BREAKER — reduce-tier, no live cross-talk) were run before any code changed. All three converged unprompted on two points: (1) don't build a second, undocumented vocabulary without recording why — this DDR is that record; (2) the new mode must not be named "Advanced," because the panel already has an "Advanced" *section* (the raw-CSS/HTML-attribute escape hatch from DDR-104 §5), and reusing the word for a *mode* collides with that.

The user, after seeing the naming-collision risk surfaced, made an informed, explicit call to override it: the **raw-CSS mode itself** is named "Advanced" (not the new Figma-vocabulary mode), on the reasoning that the raw-CSS mode nesting the raw-CSS-property escape hatch is conceptually consistent — both mean "pro-level access" — rather than confusing. This DDR records that the collision was surfaced and consciously accepted, not overlooked.

## Decision

1. **Designer mode is additive, not a replacement.** `CssKnobs` gains a `mode` state (`'advanced' | 'designer'`), default `'advanced'` — zero behavior change for existing users until they opt in, persisted via `localStorage` (`maude-cp-mode`, mirroring the existing `mdcc-sections-expanded` pattern). Advanced mode is DDR-104's original decision, byte-identical, unchanged.
2. **Designer mode is a regroup, not a 1:1 relabel.** The real pain BUILDER's opening identified: task-relevant properties are scattered across today's 8 sections (e.g. Hug/Fill/Fixed sizing lives in Size while flex properties live in Layout, even though both are "Auto layout" in Figma's mental model). Designer mode's 11 clusters (Auto layout / Size / Position / Fill / Stroke / Corner radius / Effects / Opacity / Text / Spacing / Media) cut across today's section boundaries where the Figma mental model demands it — full cluster map in the plan's Design Decisions section.
3. **Zero new control primitives, zero new write endpoint.** Every Designer-mode row is built from `CssKnobs`'s existing closures (`row`, `color`, `num`, `csel`, `tok`, `vtok`, `iconseg`, `radiusControl`, `sizeModeSeg`, `commit`) or the Phase-1 shared library (`Segmented`, `AlignPad`, `SliderField`, `NumberField`). Both modes ride the same `POST /_api/edit-css` → `editAttribute` path DDR-104 established — the DDR-054 trust boundary and DDR-104's provenance/token-first/shadow-flagging guardrails are carried forward unchanged for Designer mode.
4. **`row()` gains an optional label override**, applied to both the visible label text and the `title` tooltip together (never left out of sync — the exact gap BREAKER's opening flagged). All existing Advanced-mode call sites pass nothing and render byte-identical output.
5. **Two new real CSS rows — `filter` (blur-only, v1) and `mix-blend-mode`** — fill a genuine DDR-104 OUT-list gap (§3: both were explicitly deferred to the custom-attributes hatch). They're needed for Designer mode's "Effects" cluster to be a faithful Figma-parity surface, and since `applyEdit`/`editStyleProp` is property-name-generic (no server allowlist), they're added as real curated rows in Advanced mode's Appearance section too — not Designer-mode-exclusive. `filter` is scoped to `blur(Npx)` only in v1, not a full filter-function editor.
6. **The naming collision is accepted, not resolved.** "Advanced" now names both the raw-CSS *mode* (this DDR) and the raw-CSS/attribute *section* nested inside it (DDR-104 §5) — a conscious choice on the reasoning above, revisit only if real user confusion surfaces post-ship.

## Consequences

- Non-technical users get a Figma-familiar on-ramp; technical users keep the honest-CSS-labels panel DDR-104 built, reached via the same toggle.
- Two doors, one control: the per-corner radius detach, the Hug/Fill/Fixed sizing toggle, and every other Phase-1 primitive behave identically whether reached from Advanced or Designer mode — same underlying `commit`/`optimistic`/`authored` state, just a different render tree branch inside the same `CssKnobs` function body (not a second component — avoids the props-threading drift risk BREAKER flagged with a second render surface).
- `filter`/`mix-blend-mode` are visible and editable from Advanced mode as of this DDR — DDR-104 §3's OUT-list entry for both is now superseded; the rest of that OUT-list (`display` was already promoted by DDR-104's own addendum; `position`/`transform`/etc. — see feature-element-editing-robustness Stage B) is untouched by this DDR.
- If Designer mode's cluster map turns out wrong in practice (a cluster nobody uses, a regroup that confuses more than it clarifies), it's a presentation-layer change only — no data model, write path, or provenance logic to migrate, since Designer mode owns no state Advanced mode doesn't already have.

## Addendum — 2026-07-14 (post-ship polish, user-driven)

Two same-day refinements after the owner reviewed the shipped panel:

1. **The mode is now an App-owned, Settings-surfaced preference.** The `mode` state was lifted from `CssKnobs` to `App` (the exact single-source-of-truth pattern `theme` uses) so it's controllable from BOTH the in-panel corner toggle and **Settings → Appearance → "Inspector vocabulary"**, and the two never diverge. App owns the `maude-cp-mode` localStorage persistence; the panel and the Settings radio are controlled views. The in-panel toggle itself was demoted from a full-width `Segmented` row to a compact 2-icon `IconButtonGroup` (`{}` raw-CSS / wand Figma) in the id-row corner — the full-width bar read as far too heavy for a mode switch this minor.

2. **Designer mode suppresses the inherited-provenance dot — a conscious, scoped partial-divergence from DDR-104 §6.** DDR-104 §6 made provenance legible *per row* (token-bound / raw-override / inherited) with a dot on every row. For the developer-facing Advanced surface that's the point and is **unchanged**. But on the Designer surface the dot on every row built a "punch-card" left rail that was the single biggest driver of the visual clutter the owner flagged (measured against Figma's own dot-free panel). So under the `.st-cp--designer` root modifier ONLY, the **inherited** dot is hidden (`visibility:hidden`, the grid column stays reserved so labels never shift) — the bound/override dots stay, because "this value is customized" is useful signal even to a non-technical user and is rare enough not to form a rail. Advanced mode keeps DDR-104 §6 in full. Also under the same modifier: section headers drop mono/UPPERCASE for the body font + title case ("Auto layout" not "AUTO LAYOUT"), and row labels switch from mono to the body face — all cosmetic, Designer-scoped, reversible. The rationale is DDR-171's own thesis (Designer mode serves the audience that doesn't think in CSS), applied to provenance density rather than vocabulary; recording it so the §6 divergence is a decision, not an accident.
