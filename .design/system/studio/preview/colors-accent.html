Accent

studio runs two accent tracks. Plasma is the component accent — buttons, links, focus rings, sidebar-active, status text. Amber is a brand spotlight: docs hero, signature-moment art, the mark inset. The rule that prevents drift: plasma in chrome, amber in moments — never the other way.

Plasma — --accent

One family. Four states. Plus a tinted background (--accent-soft) for badges and a glow shadow (--accent-glow) for moments of emphasis. Used everywhere clickable.

Amber — --brand-amber

Amber lives in marketing. It's the hedgehog wink that signals "this product has personality". The Affinity playbook calls these "moments" — places where the system stops being chrome and starts being identity. Below is the canonical use: a docs hero with an ambient amber glow, a "/system" eyebrow, and the studio mark.

The line where chrome ends
and identity begins.

Plasma carries every clickable surface in studio. Amber is reserved for moments — the hero, the mark, the line that announces "a system was here". When you find yourself reaching for amber inside a button, you've already lost the argument.

The line that cannot be crossed

Two patterns the design-system-completeness-critic will flag (and a graphic-design critic will roast in a code review):

don't

Amber inside a component

Buttons, links, focus rings, and other clickable chrome use --accent — never --brand-amber. Two equal accents in the same chrome means no accent.

use --accent instead

The one-accent rule, restated: --accent* is the only accent family that lives in components. --brand-amber is namespaced under --brand-* so the completeness-critic counts it separately.

Why split at all? Because the docs hero needs personality and the dev-server status bar needs to disappear. Two surfaces, two jobs, two colors — but only one of them touches a button.
